**Shape rules (v2.13.0)**:
1. Multi-scenario cases are split into N sub-rows (one per expected behaviour); one test function per sub-row.
2. Stateful cases (breaker.json / store.json / cache.json) declare `state_mode: shared | isolate_per_case | isolate_per_test` in the Inputs row.
3. Subprocess / cross-process cases (N-series integration) declare `subprocess_mode: in_process | out_of_process` and `shared_TASKQ_HOME: bool` in the Inputs row.
4. Sub-assertion predicate LHS identifiers never use stdlib top-level module names (`json`, `os`, `sys`, `time`, `subprocess`, `pathlib`, `asyncio`, `typing`, `logging`) nor builtin shadow-prone names (`dict`, `list`, `set`, `tuple`, `str`, `int`, `bool`, `bytes`, `type`, `id`, `path`, `file`). Domain-specific synonyms are used where the prose AC naturally names such a concept.
5. Spec ambiguity is resolved by `precondition: <how to construct the scenario>` in the Inputs row or `skip_reason: spec_gap_resolved_in_pN`.
6. NFRs are layered: integration-level NFRs (`NP-06`, `NP-07`, etc.) carry concrete Inputs / Sub-assertions in §Cross-Cutting; Unit / Static NFRs are isolated in the `Deferred to Downstream Phases` table.

**Direction B (Properties)** are declared only for FRs with clean algebraic invariants; their `invariant` cell uses valid Python-expression syntax referencing case-input variables (decider-A) or symbolic production functions (decider-A degrades to non-blocking `needs_review`).
